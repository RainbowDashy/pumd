# Pull and resolve with diff3 merges

`pumd` will keep `publish` as the explicit local-to-Google-Docs operation and add a separate `pull` operation for committed, Markdown-representable remote changes; cosmetic native formatting remains reviewer-owned. A conflict-free pull atomically rewrites only affected structural units as canonical Markdown, preserves untouched source bytes and local-only edits, advances the Published Baseline to the pulled remote state, and performs no Google Docs write; the preserved local edits remain pending for a later `publish`. Disjoint local and remote changes merge automatically, while overlapping changes create a Pending Merge containing Git-style diff3 local, Published Baseline, and remote sections in the Markdown source. The author edits those markers and runs `pumd resolve`, which validates the result, verifies that Google Docs has not changed since the pull, publishes the resolved units, advances the Published Baseline, and clears the Pending Merge. `pumd pull --abort` instead restores the exact pre-pull source retained by the Pending Merge and clears that state without relying on Git. While a Pending Merge exists, `publish`, another `pull`, `move`, and `forget` are blocked; only `resolve`, `pull --abort`, and read-only listing are allowed, and the Publication is listed as `merge-conflicted`. `pumd pull --dry-run` reports incoming units, preserved local edits, conflicts, and whether a Pending Merge would begin while writing neither source nor registry state. This supersedes ADR-0010's publish-only policy because explicit two-way movement is now required without weakening three-way conflict detection.
