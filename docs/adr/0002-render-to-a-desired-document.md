# Render to a desired document

The Markdown CST renderer will produce a declarative, Google-Docs-native `DesiredDocument` rather than API write requests. Its vocabulary follows native elements such as paragraphs, text runs, bullets, tables, and inline objects; Markdown constructs are translated at the renderer boundary. Rendered elements retain their Markdown source ranges as diagnostic provenance, but that metadata is excluded from native content equality and output and must never serve as stable element identity. Google exposes document content primarily as a read model and requires ordered update requests for writes, so keeping desired state separate allows a future reconciliation step to compare desired and remote document structure before compiling minimal updates while excluding server-assigned IDs and indexes from rendering.
