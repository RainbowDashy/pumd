# Replace gcloud automation with browser-owned Project Authorization provisioning

Guided Project Authorization setup will stop invoking the Google Cloud CLI and instead hand project, API, consent, and OAuth-client provisioning to Google-owned Cloud Console flows: the Enable Docs API flow handles Google sign-in, project selection or creation, and `docs.googleapis.com` enablement, while the Auth Clients page handles OAuth app registration and Desktop client creation; `pumd` validates the downloaded Desktop client JSON and performs the direct `drive.file` installed-app OAuth flow itself. The `--client-file` shortcut and the explicit ADC route remain available, and ADC may still be provisioned with `gcloud` outside `pumd`. In exchange for removing the `gcloud` dependency and terminal account/project management, `pumd` no longer programmatically inspects or mutates cloud state, so it cannot verify a project, confirm API enablement, or detect consent configuration before the browser handoff. A second OAuth grant with Cloud-management scopes such as `cloud-platform` was rejected: it broadens the requested authorization beyond `drive.file` and still cannot create, inspect, or verify OAuth clients, because Google does not expose consent-screen or OAuth-client management to applications, so it would add scope without removing any manual Console step.
