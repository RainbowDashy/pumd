# Keep the publication registry local

`pumd` will treat the association between a Markdown source and its published Google Doc as machine-local state owned by one installation. One owner-only user-level Publication Registry in pumd's platform configuration directory is keyed by canonical absolute source path; each path has at most one active Publication, so repeated publishing updates the same document. The registry contains each Published Baseline, is replaced atomically, and serializes local mutation commands so concurrent processes cannot lose state. A source rename preserves that relationship only through an explicit local registry reassociation; pumd does not infer identity from content or silently create a replacement document. Missing sources remain registered and visible until an explicit local forget operation removes the relationship; forgetting never deletes or modifies the Google Doc. A missing, trashed, or inaccessible remote document likewise preserves the Publication and blocks publishing rather than creating a replacement. Repositories contain no publishing state. `pumd list` enumerates that registry, and publishing never uses Drive-wide search, remote custom properties, or version-controlled state to discover another installation's Publications. This deliberately gives up cross-machine recovery and shared publishing ownership in exchange for a smaller personal-tool model, while the resulting Google Doc remains available for ordinary reviewer collaboration.
